## Current transport defects
1. `custom-mobile-scroll.js` attaches globally to the package button name instead of a specific form/context.
2. On job submission it omits the `job_id` cart payload and bypasses the native Paid Listings form handler that is protected by `Raspitajse_Commerce_Job_Package_Policy`.
3. It hardcodes `/?wc-ajax=add_to_cart`, `/checkout/`, and `/?add-to-cart=ID` instead of consuming generated Woo URLs.
4. It calls `update_order_review` after add-to-cart. The dashboard request does not enqueue `wc-checkout`, so there is no valid checkout update nonce; the call is unnecessary before checkout.
5. The child script declares only `jquery`, while Woo's `wc-add-to-cart` values are localized at print time. Depending implicitly on those globals would remain load-order fragile.
6. Its GET fallback can repeat a failed add with a second transport and can mask the original failure.

## Approved-design target contract

### Job submission
- Do not intercept `#job_package_selection button[name="wjbpwpl_job_package"]`.
- Preserve the native form submission, nonce, form name, submit step, object/job ID, cookie/step transition, and Paid Listings cart mapping.
- Keep the Raspitajse-owned canonical policy wrappers as the authorization boundary.
- Do not modify Paid Listings, WPJBP, WooCommerce, Superio parent, or other vendor files.

### Standalone dashboard purchase
- Own transport in `raspitajse-commerce`, not in the child theme.
- Enqueue an owned asset only on `page-dashboard.php`; scope its handler strictly to `.wjbpwpl-packages-form button[name="wjbpwpl_job_package"]`.
- The plugin supplies a namespaced immutable view/config object containing:
  - add-to-cart URL generated with Woo's endpoint API (`WC_AJAX::get_endpoint('add_to_cart')`);
  - checkout URL from `wc_get_checkout_url()`;
  - localized pending/failure copy only.
- Post exactly one add-to-cart request with the selected product ID and quantity 1.
- On a valid Woo success response, apply returned fragments when present, emit the normal fragment event for compatible presentation, then navigate to the localized checkout URL.
- On Woo `error + product_url`, follow only Woo's returned same-origin product URL; otherwise fail closed, restore the button, and show a non-sensitive localized message.
- On network failure, restore the button and show failure. Do not perform a GET retry and do not redirect to a hardcoded URL.
- Never call `update_order_review`; checkout owns its own recalculation lifecycle.
- JavaScript controls pending UX only. It must not decide entitlement availability, expiry, quota, ownership, or revocation.
