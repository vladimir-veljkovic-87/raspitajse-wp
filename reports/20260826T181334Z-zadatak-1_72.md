## Problem statement
The active submit and dashboard renderers both read entitlement metadata and duplicate presentation calculations/status labels. Submit shows used quota, while the target UX needs remaining quota. The dashboard full-file override also contains unreachable branches for non-job package types. A small owned view model can centralize safe read-only interpretation without moving authorization into templates or JavaScript.

## Canonical API contract
Add two public read-only methods to `Raspitajse_Commerce_Job_Package_Policy`:

```php
public static function get_view_model(
    $user_id,
    $entitlement_id,
    $now_timestamp = null
);

public static function get_view_models_by_user(
    $user_id,
    $include_revoked = true,
    $now_timestamp = null
);
```

### `get_view_model()` return contract
Return `null` when the object is missing, is not `job_package`, has the wrong package type, or is not owned by the normalized user. This avoids exposing another owner's entitlement.

For an owned employer job entitlement, return an associative array with fixed types:

| Key | Type | Contract |
|---|---|---|
| `id` | int | entitlement post ID |
| `title` | string | stored entitlement snapshot title |
| `status` | string | exact result of canonical `get_status()` |
| `usable` | bool | true only when status is `available` |
| `used` | int | non-negative package count snapshot |
| `limit` | int | non-negative entitlement job limit snapshot |
| `unlimited` | bool | true only when `limit === 0` |
| `remaining` | int|null | `null` for unlimited; otherwise `max(0, limit - used)` |
| `activated_at` | int | canonical activation timestamp or 0 |
| `valid_until` | int | canonical expiry timestamp or 0 |
| `job_duration_days` | int | individual job duration snapshot; never package validity |
| `urgent_jobs` | bool | normalized entitlement feature flag |
| `featured_jobs` | bool | normalized entitlement feature flag |

### Status and authorization invariants
- `status` must be obtained by calling existing `get_status()`; the view model must not reimplement status order or expiry/quota rules.
- `usable` is exactly `STATUS_AVAILABLE === status`.
- `remaining` is presentation data only and must never authorize a job.
- Wrong owner/non-job objects return `null`; own publish objects with incomplete canonical metadata return a model with `status=unavailable` and `usable=false`.
- Cancelled own entitlements return `status=revoked` when `include_revoked=true`.
- No `_wjbp_package_expiration_*`, completed-order lookup, product-name lookup, raw SQL/postmeta fallback, user write, or render-time write is allowed.
- No filters may override `status` or `usable` in the first implementation.

### Feature flag normalization
Paid Listings creates entitlement feature flags as `on`; historical/plugin variants may contain `yes`, `1`, integer `1`, or boolean true. The view model may normalize only these explicit truthy representations. Feature flags are presentation/entitlement attributes, not package validity.

### Collection method
`get_view_models_by_user()` must:
1. normalize the user through the existing canonical path;
2. call existing `get_packages_by_user()`;
3. build each model through `get_view_model()`;
4. omit `null` models;
5. preserve canonical query ordering;
6. perform no writes.

## Presentation contract
Templates may:
- render title, canonical status, remaining/total, validity date, and individual job duration;
- use `usable` to emit `checked`/`disabled` UI state;
- format timestamps with WordPress timezone/date settings;
- localize labels and apply semantic CSS classes.

Templates/JS may not:
- calculate expiry or status;
- infer access from orders, products, names, body classes, CSS, or dates;
- enable a model where `usable=false`;
- treat 15/30-day individual job duration as package validity.

Server handlers remain the final and repeated authorization layer regardless of UI state.
