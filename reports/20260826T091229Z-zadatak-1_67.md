## 2. Purchase, entitlement and listing-duration separation
### A. Purchase/order validity
- Pending/on-hold/failed do not create an entitlement.
- Processing/completed activate in current vendor behavior.
- Cancelled/refunded revoke through status hooks.
- Paid Listings does not re-check the Woo order each time a package is used; lifecycle callbacks are expected to project order state into entitlement state.

### B. Package entitlement validity
- The storage object is job_package.
- There is no vendor calendar-expiration field for active employer job packages.
- Current effective vendor model is owner plus quota, with published status applied by package queries but missing from direct package_is_valid().
- Legacy _wjbp_package_expiration_* user meta is a UI-only parallel model and is not backend authorization.

### C. Job listing duration
- Start: each job receives 15 days.
- Pro: each job receives 30 days.
- Partner: each job receives 30 days.
- This duration is copied to the entitlement and then the job; it must not be interpreted as entitlement validity.

## 5. Cancellation and refund behavior
| Order status/event | Current entitlement result | Existing linked jobs | Idempotency/risks |
| --- | --- | --- | --- |
| pending | None created | No package action | No activation hook |
| on-hold | None created | No package action | No activation hook |
| processing | Creates entitlement(s) | Optional pending-payment job is approved with new entitlement | Processed marker prevents normal completed duplication, but uses raw order postmeta under HPOS |
| completed | Same activation callback | Same | Marker normally prevents a second creation after processing |
| cancelled | Published entitlement becomes cancelled | publish/expired/pending linked jobs become cancelled | Cancel marker is written but not checked; published-only query makes repeated revoke mostly inert |
| fully refunded/status refunded | Same as cancelled | Same as cancelled | Depends on parent order reaching refunded status |
| partially refunded | No Paid Listings action unless parent status separately changes | Unchanged | Business behavior NOT DEFINED |
| failed before activation | No entitlement | Unchanged | No handler |
| failed after processing | Existing entitlement remains published | Existing jobs remain | AUTHORIZATION GAP; business behavior NOT DEFINED |

Answers:
1. Entitlement is created on processing or completed.
2. The processed marker prevents the ordinary processing-to-completed duplicate, but current raw order-meta handling is not an acceptable HPOS-safe contract.
3. It is revoked on cancelled or refunded by setting the entitlement post status to cancelled.
4. Current vendor behavior cancels linked published, expired and pending jobs.
5. Partial refund has no package effect.
6. Failed after processing has no revoke effect.
7. A processed marker exists; a cancelled marker is written but not used as a guard.

A cancelled/refunded order moved back to processing/completed will not reactivate its entitlement because the processed marker remains while the entitlement remains cancelled.
