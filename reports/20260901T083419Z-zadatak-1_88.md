- Legacy 15-day behavior is not used.

Machine comparisons use UTC. Calendar boundaries are calculated with wp_timezone or an explicitly injected bounded synthetic timezone.

## 13. State-transition contract

| Current condition | Persist before side effect | Mail | Next state |
|---|---|---|---|
| New/regular due with selected IDs | Window, exact snapshot, attempt number, outcome snapshot | One owned candidate_alerts attempt | accepted, retryable, or terminal |
| Empty selection | Window and evaluated-empty outcome | None | complete empty; next due advances |
| Mail false/WP_Error, attempt 1 | Same window/snapshot | Failed | retryable; +1 hour |
| Mail false/WP_Error, attempt 2 | Same window/snapshot | Failed | retryable; +6 hours |
| Mail false/WP_Error, attempt 3 | Same window/snapshot | Failed | terminal-failed; next regular due |
| Mail true | FIRST mail-accepted window/time | Accepted handoff | reconcile ledger, complete delivered |
| Accepted state recovered | Accepted marker already present | None | reconcile ledger, complete |
| Ledger reconciled but completion interrupted | Accepted marker and ledger present | None | complete state/next due |
| Config hash changed before acceptance | New revision/cutoff, old snapshot discarded | None | config reinitialized, initial pending |
| Unknown/impossible state | No transition | None | WP_Error fail closed |

State permits only the exact known schema keys. Unknown/PII-like extra fields are rejected.
